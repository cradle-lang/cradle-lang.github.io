# Announcing CradleXC 0.19.0

<!-- markdownlint-disable-next-line MD036 -->
*22 September 2026*

CradleXC 0.19.0 expands the production `cxc` workflow with content-driven
configuration and heuristic resolution. Scenario authors can keep reusable
configs and heuristic implementations in a local directory or Git repository,
while the compiler uses packaged heuristic metadata to fill in compatible
requirements before validation.

The release also makes backend generation easier to operate and diagnose.
Layered content directories, clearer incremental rebuild behavior, shell
completion installation, and additional configuration controls reduce manual
setup while keeping target-specific generation separate from deployment.

## Highlights

* Infer compatible `os()` and `config()` requirements from heuristic metadata.
* Use local or Git-backed content repositories with optional layered directories.
* Generate shell completions during package installation.
* Configure controller-side forensic extraction output with `dataset_dir`.
* Improve `cxc doctor` formatting and make backend discovery and build state more explicit.

## Added

### Heuristic-driven requirements

Instances can derive missing operating-system and configuration requirements from
the heuristic metadata packaged with CradleXC. Matching heuristic requirements
are applied before validation, including configuration entries needed by the
heuristic.

An explicit `os()` always wins. If matching heuristics imply different operating
systems and the instance has no explicit `os()`, CradleXC reports an error and
leaves the operating system unresolved. If an explicit operating system conflicts
with an implied one, CradleXC keeps the explicit value and reports a warning.

### Layered configuration and heuristic content

`config_dir` and `heuristics_dir` can be local directories or Git URLs. Build
workflows fetch referenced content on demand when a Git URL is used. Additional
directories can supply content missing from the primary directory without
overriding it:

```bash
cxc build \
  -i scenarios/HelloWorld.cradle \
  --target vagrant \
  --extra-config-dir ./project-configs \
  --extra-heuristics-dir ./project-heuristics
```

Use `cxc configs list` and `cxc heuristics list` to inspect available content.

### Shell completions

The package installation generates shell completion definitions. Completions
can also be generated directly when maintaining a manual installation:

```bash
cxc completions bash
```

## Changed

### Configuration and extraction output

The configuration now supports `dataset_dir`, which defaults to
`/opt/cxc/dataset` and controls the controller-side base directory for forensic
extraction output. `CXC_DATASET_DIR` can override the value. Backend-specific
configuration is preferred when different backends need different controller
paths.

The CLI uses the `Cradle Cross Compiler` product name in its help and diagnostic
output. `cxc doctor` now reports the configured file, config directory, and
heuristics directory with a clearer dependency table. Its dependency rows vary
with the installed backend environment.

### Build and rebuild workflow

`cxc rebuild` continues to regenerate the complete file set from the saved
build-state snapshot rather than applying a partial file update. Changes to
configuration, heuristics, operating-system requirements, or other
deployment-relevant inputs are classified before rendering. Generated files are
updated only; CradleXC does not create, change, or remove a live deployment.

## Fixed

### Content resolution and generated metadata

Git-backed config and heuristic content is resolved per referenced item, with
manifest metadata used to discover heuristic requirements. The packaged
heuristics database is installed at `/opt/cxc/heuristics.db`, and the default
content paths no longer depend on a compiled-in config bundle.

Generated file headers no longer carry the obsolete internal `v2` label.
Extraction output can use the configured dataset directory instead of relying
on a fixed path.

## Installation and upgrade

Install or upgrade the CradleXC package through the CRADLE APT repository:

```bash
sudo apt update
sudo apt install cxc
```

After upgrading, verify the version and local environment:

```bash
cxc --version
cxc doctor
```

Review existing configuration files for the new `dataset_dir` setting when
forensic extraction output must remain in a site-specific location. Existing
`config_dir` and `heuristics_dir` values continue to work as local paths or Git
URLs; use the new layered options when project-specific content should
supplement, rather than replace, shared content.
