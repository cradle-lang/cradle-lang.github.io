# Announcing CradleXC 0.19.3

<!-- markdownlint-disable-next-line MD036 -->
*9 October 2026*

CradleXC 0.19.3 improves the reliability of scenario validation and
network-aware generation. It rejects event definitions that would have
nothing to execute or would leave an interpreter waiting on standard input,
and it derives routes across connected routers instead of stopping at the
first hop.

The release also makes the compiler's host-only gateway handling
backend-neutral: a spare gateway address is used when available, but its
absence is not treated as a compiler error. This helps container-oriented
backends use compact networks while backends that require a gateway can
report that requirement themselves.

## Highlights

* Reject empty event commands before they can produce a hanging deployment.
* Infer routes through multi-router topologies in Deployment IR.
* Treat host-only gateway allocation as best effort during lowering.
* Document the backend plugin protocol, heuristics, rebuild semantics and
  release workflow in the upstream project.

## Changed

### Event validation prevents commands with nothing to run

When an event has no `runObject()`, CradleXC now rejects an empty
`subject()` with diagnostic `E013`. It also rejects a bare interactive
interpreter such as `bash` with no command or script using `E014`. These
checks prevent generated tasks from silently doing nothing or waiting
indefinitely for input.

Provide a command explicitly:

```cradle
event("run_command") >
    subject("bash", "-c 'echo ready'").
```

Alternatively, use `runObject()` when the event should execute a script
artifact. A bare interpreter remains valid when a `runObject()` supplies the
script.

### Routing follows connected router paths

CradleXC now models routers as a graph and infers deterministic routes to
networks beyond an instance's directly connected router. In a chained
topology, both routers receive routes for networks on the far side, while a
non-router guest uses its local router as the next hop.

The selected backend still determines how these routes are rendered and
applied. Inspect the Deployment IR with `cxc dump-ir` when verifying the
calculated destinations and gateways.

### Host-only gateway allocation is best effort

The compiler no longer requires a spare address in every subnet for a
host-only gateway. This permits valid point-to-point networks with no unused
address and avoids imposing a VM-backend assumption on the backend-neutral
Deployment IR. A backend that requires a host-only gateway remains
responsible for reporting that constraint during rendering.

## Documentation

The upstream CradleXC project adds reference material for the external
backend-plugin protocol, heuristic content, complete rebuild behavior and the
compiler-first release process. These topics clarify which responsibilities
belong to CradleXC, backend plugins and the release workflow.

## Installation and upgrade

Install or upgrade through the CRADLE APT repository:

```bash
sudo apt update
sudo apt install cxc
```

Confirm the installed version and inspect the local environment:

```bash
cxc --version
cxc doctor
```

Existing scenarios that use an empty event subject or a bare interpreter
without `runObject()` must be corrected before validation succeeds. Scenarios
with multi-router networks can use the inferred routes, subject to the
capabilities and requirements of the selected backend.
