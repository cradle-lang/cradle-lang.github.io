# Announcing CradleXC 1.0.0

<!-- markdownlint-disable-next-line MD036 -->
*28 August 2026*

CradleXC 1.0.0 is the first public release of the CRADLE command-line toolchain for defining and processing reproducible cyber-range scenarios.

CRADLE provides a declarative domain-specific language for describing systems, networks, artifacts and scenario events in a structured `.cradle` specification. CradleXC provides the tooling to validate, inspect and compile those scenarios before generating target-specific files through independently distributed backend plugins.

This release establishes the initial public workflow for authoring CRADLE scenarios, diagnosing source and environment issues and separating scenario definitions from deployment-specific generation.

## Highlights

* Define reproducible cyber-range scenarios using declarative `.cradle` source files.
* Validate scenario syntax and obtain detailed diagnostics before generation.
* Compile scenarios into structured YAML and inspect CradleXC's intermediate representation.
* Extend target-specific generation through independently distributed backend plugins.
* Generate deployment files without coupling CRADLE scenarios to a specific target platform.
* Diagnose local dependencies and inspect active CradleXC configuration from the command line.

## Added

### Scenario validation and diagnostics

Use `cxc validate` to parse the source and validate its syntax and structure:

```bash
cxc validate -i <scenario.cradle>
```

Structured diagnostics are also available for tooling and automation:

```bash
cxc validate -i <scenario.cradle> --json
```

This allows source problems to be identified before compilation or backend processing.

### Scenario compilation

Valid CRADLE scenarios can be compiled into a structured YAML representation:

```bash
cxc compile \
  -i <scenario.cradle> \
  -o <output.yml>
```

This provides a machine-readable representation of the human-authored scenario for inspection and downstream processing.

### Intermediate representation inspection

CradleXC exposes its intermediate representation through:

```bash
cxc dump-ir -i <scenario.cradle>
```

This provides visibility into how CradleXC interpreted a scenario and can assist with troubleshooting compiler output and backend integration.

### Backend plugins

Target-specific generation is provided through external backend plugins rather than being built directly into CradleXC.

Published plugins can be installed with:

```bash
sudo cxc plugin install <plugin_name>
```

Backend executables follow the naming convention:

```text
cxc-backend-<name>
```

The default installation is system-wide in `/opt/cxc/plugins/`. CradleXC discovers compatible backend executables from the system `PATH`, `/opt/cxc/plugins/` and the per-user `~/.cxc/plugins/` directory.

Available backends can be inspected with:

```bash
cxc backend list
```

Keeping backend implementations separate allows the core CRADLE workflow to remain independent of a particular deployment target or provider.

### Target-specific generation

Once a compatible backend is available, `cxc build` generates the files required by the selected target:

```bash
cxc build \
  -i <scenario.cradle> \
  --target <plugin_name> \
  -o <output_directory>
```

CradleXC generates target-specific files but does not automatically execute or provision the resulting infrastructure. Generated files remain under the user's control and are used with the corresponding tooling in the target testbed environment.

After changing a scenario, `cxc rebuild` compares it with the last successful build and regenerates the complete file set in the same output directory:

```bash
cxc rebuild \
  -i <scenario.cradle> \
  --target <plugin_name> \
  -o <existing_output_directory>
```

### Environment diagnostics

CradleXC includes built-in commands for checking the local environment and configuration.

Run:

```bash
cxc doctor
```

to check dependencies and environment readiness.

If dependencies are missing, installation guidance can be displayed with:

```bash
cxc install-deps
```

The active CradleXC configuration can be inspected with:

```bash
cxc config
```

These commands provide a consistent way to diagnose installation, dependency and backend-related environment issues.

## Installation and upgrade

CradleXC is distributed as a prebuilt package for Ubuntu and Debian through the CRADLE APT repository.

After configuring the CRADLE package repository, refresh the package index and install CradleXC:

```bash
sudo apt update
sudo apt install cxc
```

Verify the installation with:

```bash
cxc --version
cxc doctor
```

As this is the inaugural public release, there is no previous public CradleXC release to upgrade from.
