# Announcing CradleXC 0.16.0

<!-- markdownlint-disable-next-line MD036 -->
*12 September 2026*

CradleXC 0.16.0 is a source-distributed release of the CRADLE compiler and
command-line toolchain for building, deploying and examining cyber-range
scenarios.

This release is aimed at scenario authors and operators who need one CLI for
the complete workflow: validate and compile `.cradle` source, render or deploy
through a selected backend, and extract forensic data afterward. Backend
implementations are separate plugins, so the core CLI can evolve independently
of a specific testbed provider.

The release also makes the compiler pipeline and configuration visible through
dedicated inspection commands. That separation helps users distinguish
source validation, generated files, live deployment stages and post-run
forensic extraction.

## Highlights

* Compile CRADLE scenarios through validated HIR and Deployment IR stages.
* Render target files without deployment, or run explicit deployment stages.
* Discover external `cxc-backend-<name>` plugins through the CLI.
* Import supported static Vagrant/Ansible layouts into validated CRADLE source.
* Generate C and PowerShell artifacts from YAML definitions.
* Inspect dependencies and active runtime configuration with `cxc doctor` and
  `cxc config`.

## Added

### Pluggable backend workflow

CradleXC no longer requires a deployment backend to be compiled into the CLI.
Install a compatible `cxc-backend-<name>` executable on `PATH`, then inspect
what the CLI can discover:

```bash
cxc backend list
```

Use `cxc emit` to render target-specific files without running deployment
stages:

```bash
cxc emit -i hello.cradle --target vagrant -o ./output
```

Use `cxc deploy --backend <name>` when the selected backend should compile,
render, provision and run the scenario workflow. Backend-specific settings can
be passed repeatedly with `--backend-arg key=value`.

### Compiler-stage inspection

The CLI exposes parse, semantic-check, HIR and Deployment IR stages:

```bash
cxc parse -i hello.cradle
cxc check -i hello.cradle --json
cxc dump-hir -i hello.cradle
cxc dump-ir -i hello.cradle
```

The Deployment IR emitted by `dump-ir` is the backend-neutral input for plugin
rendering. These commands inspect compiler output; they do not deploy a
scenario.

### Import and forensic extraction

Static Vagrant/Ansible layouts can be converted into validated CRADLE source:

```bash
cxc import --from ./deployment --name ImportedLab \
  --output scenarios/ImportedLab.cradle
```

After a deployment, extract forensic data separately:

```bash
cxc extract --scenario ImportedLab --deploy-dir ./output/ImportedLab
```

The importer cannot reconstruct dynamic Ruby, Ansible includes, roles or
arbitrary module behavior. Review its warnings before using the generated
scenario.

### Artifact generation

Generate an individual artifact or all objects described by a project index:

```bash
cxc generate-artifacts -i artifact.yml -o ./build
cxc generate-artifacts -i index.yaml -o ./build --project
```

## Changed

### Source installation and runtime dependencies

CradleXC 0.16.0 is installed from source with Cargo:

```bash
cargo install --path crates/cradle-cli
```

The core CLI does not compile deployment backends into the binary. Required
runtime tools therefore depend on the external backend selected by the user.
Run `cxc doctor` to see discovered backend checks and `cxc install-deps` for
platform-specific guidance.

### Configuration

Configuration is TOML and supports artifact and forensic paths, deployment
defaults, hardware defaults and per-backend option tables. The global
`--config <path>` option selects a file for one invocation:

```bash
cxc --config ./config.toml doctor
```

Environment variables can override supported runtime settings. Consult the
configuration example and the installed command help for the exact options
provided by this release.
