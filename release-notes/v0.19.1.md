# Announcing CradleXC 0.19.1

<!-- markdownlint-disable-next-line MD036 -->
*22 September 2026*

CradleXC 0.19.1 fixes a production issue in remote `config_dir` workflows.
When a scenario relies on generated routing templates such as `linux-routing` or
`win-routing`, CradleXC now treats those names like any other config entry during
content fetch and validation instead of skipping them. This keeps Git-backed
config repositories consistent with local directories and prevents avoidable
build failures for route-based environments.

This correction matters for teams using hosted or shared config content and for
layers that rely on route metadata to generate backend-specific files. The fix is
small and targeted: the CLI continues to resolve prior content the same way, but
it now materializes the route configs that production builds expect.

## Highlights

* Fix Git-backed `config_dir` resolution for auto-generated `linux-routing` and
  `win-routing` configs.
* Keep route-aware builds consistent across local and remote config sources.
* Preserve existing `cxc build` and `cxc rebuild` behavior while removing the
  fetch gap.

## Fixed

### Remote config fetches for route templates

`cxc build` and `cxc rebuild` now fetch `linux-routing` and `win-routing`
entries from a Git-backed `config_dir` before validation and rendering.
Previously those virtual route configs were skipped during sparse fetch, which
could leave a remote config repo incomplete and cause a later configuration
error even though the scenario was otherwise valid.

This fix applies uniformly to the configured content source and any layered
extra directories. If a scenario uses a routing requirement, CradleXC now
resolves the generated config the same way it resolves other config names.

## Installation and upgrade

Install or upgrade through the CRADLE APT repository as usual:

```bash
sudo apt update
sudo apt install cxc
```

After upgrading, validate the local environment:

```bash
cxc --version
cxc doctor
```
