# Announcing CradleXC 0.15.0

*24 August 2026*

CradleXC 0.15.0 is the first public release of the CRADLE command-line toolchain.

CradleXC provides the core workflow for validating, inspecting, compiling and transforming declarative `.cradle` scenarios. It enables users to check scenario definitions before generation, inspect structured representations and produce deployment-specific files through independently distributed backend plugins.

This release establishes a separation between CRADLE scenario definitions and individual deployment platforms. Scenarios are processed by CradleXC while backend plugins handle target-specific generation for supported environments.

CradleXC 0.15.0 also introduces environment diagnostics and configuration inspection to help users prepare and troubleshoot their local installation.

## Highlights

* Validate CRADLE scenarios and receive detailed diagnostics before generation.
* Compile `.cradle` scenarios into structured YAML.
* Inspect CradleXC's intermediate representation for troubleshooting and backend development.
* Install and discover independently distributed backend plugins.
* Generate target-specific deployment files without coupling scenarios to a single platform.
* Diagnose local dependencies and inspect the active CradleXC configuration.

## Breaking changes

### Backend implementations are distributed separately

Backend implementations are no longer bundled with the core CradleXC package.

Users who require a deployment backend must install the appropriate plugin separately before generating target-specific files.

Install a published backend with:

```bash
cxc plugin install <plugin_name>
```

For example:

```bash
cxc plugin install vagrant
```

Verify that CradleXC can discover the installed backend with:

```bash
cxc backend list
```

Vagrant, SPHERE and libvirt-Ansible backend support are separated from the core package so that CradleXC and individual deployment backends can be developed and released independently.

Plugins installed locally under:

```text
~/.cxc/plugins/
```

are removed when the core `cxc` package is uninstalled. Reinstall the required plugins after reinstalling CradleXC.

## Added

### Scenario validation and diagnostics

CradleXC provides multiple levels of scenario validation so problems can be identified before deployment artifacts are generated.

Use `cxc validate` for syntax validation:

```bash
cxc validate -i scenarios/HelloWorld.cradle
```

For more detailed diagnostics, use:

```bash
cxc check -i scenarios/HelloWorld.cradle
```

Structured JSON diagnostics are also available for editor integrations, scripts and other automated tooling:

```bash
cxc check -i scenarios/HelloWorld.cradle --json
```

### Scenario compilation

`cxc compile` converts a valid CRADLE scenario into structured YAML:

```bash
cxc compile \
  -i scenarios/HelloWorld.cradle \
  -o HelloWorld.yml
```

The generated representation provides an inspectable form of the scenario before backend-specific generation.

### Intermediate representation inspection

For lower-level inspection, `cxc dump-ir` displays CradleXC's intermediate representation:

```bash
cxc dump-ir -i scenarios/HelloWorld.cradle
```

This is useful when troubleshooting how a scenario has been interpreted or when developing backend integrations.

### Backend plugin support

CradleXC supports independently distributed deployment backends.

Compatible backend executables follow the `cxc-backend-*` naming convention and are discovered from the system `PATH` and the local CradleXC plugin directory:

```text
~/.cxc/plugins/
```

Installed backends can be inspected with:

```bash
cxc backend list
```

CradleXC and compatible backend plugins perform a compatibility handshake before target-specific operations. This helps identify incompatible plugin or intermediate-representation versions before generation begins.

### Target-specific generation

`cxc emit` generates deployment artifacts through a compatible backend:

```bash
cxc emit \
  -i scenarios/HelloWorld.cradle \
  --target vagrant \
  -o ./output
```

The files produced and their requirements depend on the selected backend.

`cxc emit` generates deployment material only. It does not start virtual machines, provision infrastructure or execute the generated files.

### Environment diagnostics

`cxc doctor` checks the local environment and reports dependencies required by installed backend plugins:

```bash
cxc doctor
```

If dependencies are missing, `cxc install-deps` provides platform-specific installation guidance:

```bash
cxc install-deps
cxc doctor
```

The active CradleXC configuration can be inspected with:

```bash
cxc config
```

## Changed

### Runtime dependencies

The prebuilt CradleXC package does not require Rust, Cargo or Git as runtime dependencies.

Users installing the packaged CLI therefore do not need the Rust development toolchain solely to run CradleXC.

Backend plugins can define and report their own platform-specific requirements.

## Installation and upgrade

CradleXC is distributed through the official CRADLE package repository.

After configuring the repository on Ubuntu or Debian, install CradleXC with:

```bash
sudo apt update
sudo apt install cxc
```

After installation, verify the local environment with:

```bash
cxc doctor
```

Users who require target-specific generation should install the corresponding backend plugin separately:

```bash
cxc plugin install <plugin_name>
```

Then confirm that the backend is available:

```bash
cxc backend list
```

To inspect the commands supported by the installed version:

```bash
cxc --help
```

For command-specific options:

```bash
cxc <command> --help
```

The installed CLI should be treated as the authoritative source for version-specific command options.
