# CLI Overview

CradleXC provides the `cxc` command-line interface for working with CRADLE scenarios.

The CLI is used to:

- validate CRADLE source
- compile scenarios
- inspect intermediate output
- inspect configuration
- manage dependencies
- discover backend plugins
- generate target-specific files

## Check the installed version

Confirm that CradleXC is installed with:

```bash
cxc --version
```

For installation instructions, see [Install CradleXC](../getting-started/install-cradlexc).

## View command help

Use:

```bash
cxc --help
```

to display the available commands and options for the installed CradleXC version.

For help with a specific command, use:

```bash
cxc <command> --help
```

For example:

```bash
cxc validate --help
```

or:

```bash
cxc compile --help
```

:::note
The exact command options available can vary between CradleXC releases. Use `--help` to confirm the interface provided by the version installed on your system.
:::

## Core workflow

The most common workflow uses:

```text
cxc validate
cxc compile
cxc dump-ir
cxc build
```

## Validate a scenario

Use `cxc validate` to parse a scenario and check its syntax and structure:

```bash
cxc validate -i <scenario.cradle>
```

For example:

```bash
cxc validate -i scenarios/HelloWorld.cradle
```

Validation reports syntax problems that need to be corrected before continuing.

For more information, see [Validate and Compile](../getting-started/validate-and-compile).

## Compile a scenario

Use `cxc compile` to compile a CRADLE scenario into YAML:

```bash
cxc compile \
  -i <scenario.cradle> \
  -o <output.yml>
```

For example:

```bash
cxc compile \
  -i scenarios/HelloWorld.cradle \
  -o HelloWorld.yml
```

The resulting YAML is the compiled representation produced by CradleXC.

## Inspect the intermediate representation

Use `cxc dump-ir` when you need to inspect how CradleXC interpreted the source scenario:

```bash
cxc dump-ir -i <scenario.cradle>
```

For example:

```bash
cxc dump-ir -i scenarios/HelloWorld.cradle
```

This command is mainly useful for inspection, diagnostics and backend development.

It is not required during every normal workflow.

For more information, see [Inspect Output](../getting-started/inspect-output).

## Generate target-specific files

CradleXC uses external backend plugins for target-specific generation.

Use:

```bash
cxc build \
  -i <scenario.cradle> \
  --target <plugin_name> \
  -o <output_directory>
```

For example:

```bash
cxc build \
  -i scenarios/HelloWorld.cradle \
  --target vagrant \
  -o ./output
```

The selected backend generates files for its supported target.

To regenerate an existing output directory after changing the scenario, use
the previous build as a comparison baseline:

```bash
cxc rebuild \
  -i scenarios/HelloWorld.cradle \
  --target vagrant \
  -o ./output
```

`cxc rebuild` reports what changed and rewrites the complete generated file
set. It does not modify a live deployment. See the
[Command Reference](./command-reference#cxc-rebuild) for its baseline and
network-change rules.

:::important
CradleXC does not automatically execute backend-generated files. Use those files with the corresponding tools in your own testbed environment.
:::

For backend setup and usage, see [Use a Backend](../getting-started/use-a-backend).

## Backend commands

CradleXC provides commands for working with backend plugins.

### List backends

Use:

```bash
cxc backend list
```

to list compatible backend plugins currently discovered by CradleXC.

Backend executables follow the convention:

```text
cxc-backend-<name>
```

CradleXC discovers compatible backend executables from the system `PATH`, `/opt/cxc/plugins/` or:

```text
~/.cxc/plugins/
```

### Install a plugin

Use:

```bash
sudo cxc plugin install <plugin_name>
```

to install a backend plugin.

For example:

```bash
sudo cxc plugin install vagrant
```

Backend installation and discovery are documented in [Use a Backend](../getting-started/use-a-backend).

## Check dependencies

Use:

```bash
cxc doctor
```

to inspect dependencies required by the current CradleXC environment.

If dependencies are missing, view installation guidance with:

```bash
cxc install-deps
```

For installation-related information, see [Install CradleXC](../getting-started/install-cradlexc).

## View configuration

Use:

```bash
cxc config
```

to inspect the current CradleXC configuration.

Configuration can include values used by the CLI and local environment.

Detailed configuration documentation is provided in [CLI Configuration](./configuration).

## CLI responsibilities

The CLI sits between CRADLE source and the other CradleXC processing stages.

| Area | Responsibility |
| --- | --- |
| Source validation | Check CRADLE syntax. |
| Compilation | Produce the compiled representation. |
| Inspection | Expose intermediate representation and diagnostics. |
| Import | Convert supported external definitions into CRADLE source. |
| Backend discovery | Locate compatible external backend plugins. |
| Backend generation | Pass a scenario to a selected backend for target-specific output. |
| Environment checks | Inspect dependencies and configuration. |

## CLI and backend boundaries

Backend commands do not make target-specific functionality part of CradleXC itself.

The separation remains:

<div className="architecture-flow">

  <div><code>cxc</code></div>

  <span>↓</span>

  <div className="architecture-flow-step-backend">External backend plugin</div>

  <span>↓</span>

  <div>Generated target-specific files</div>

</div>

Backend executables remain separate components from the core CradleXC CLI.

## Troubleshooting CLI commands

If a command fails, start by checking:

```bash
cxc --version
```

then:

```bash
cxc doctor
```

For command-specific usage:

```bash
cxc <command> --help
```

For example:

```bash
cxc build --help
```

See [Troubleshooting](../guides/troubleshooting) for additional diagnostic guidance.
