# Configuration

CradleXC reads local settings from `~/.cxc/config.toml` by default. Pass `--config <path>` to use another file, or run `cxc config` to inspect the configuration in use.

## Core paths

```toml
# Local directory or Git URL containing configuration implementations.
config_dir = "https://github.com/cradle-lang/cradle-lib"

# Local directory or Git URL containing heuristic implementations.
heuristics_dir = "https://github.com/cradle-lang/cradle-lib"

# Base repository used when a scenario does not set repositoryRemote.
artifact_repo = "/srv/cradle/artifacts"

# Local staging directory for resolved artifacts.
artifact_dir = "/srv/cradle/staging"
```

`config_dir` and `heuristics_dir` provide content used during `build` and `rebuild`. `artifact_repo` is a fallback source location. `artifact_dir` is a local working location; it is not the same thing as the repository itself.

## Backend settings

The `[deployment]` table contains defaults that a backend may use while rendering target files. Available settings and their effects depend on the selected backend.

```toml
[deployment]
timezone = "Asia/Singapore"
windows_timezone = "Singapore Standard Time"
dns_server = "192.168.56.2"
use_nfs = false
```

Backend-specific string options belong in `[backend.<name>]` tables. Command-line `--backend-arg key=value` options take precedence over matching table values.

## Check configuration

```bash
cxc config
cxc --config ./config.toml config
cxc doctor
```

See [Artifact Repositories](./artifact-repositories) for how local settings interact with scenario metadata.
