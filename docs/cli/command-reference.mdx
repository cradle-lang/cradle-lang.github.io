# Command Reference

This page summarizes the CradleXC v0.16.0 `cxc` command-line interface. Use
`cxc --help` and `cxc <command> --help` for the exact options in an installed
build.

## Command summary

| Command | Purpose |
| --- | --- |
| `cxc validate` | Validate a `.cradle` scenario. |
| `cxc compile` | Compile a scenario to intermediate YAML. |
| `cxc migrate` | Convert v1 syntax to v2.0 syntax. |
| `cxc import` | Convert a Vagrant/Ansible deployment into a `.cradle` file. |
| `cxc deploy` | Compile, render, provision and run events through a backend. |
| `cxc emit` | Render target files without deploying them. |
| `cxc destroy` | Tear down a deployment through its backend. |
| `cxc extract` | Extract forensic data from deployed VMs. |
| `cxc generate-artifacts` | Generate scenario artifacts from YAML. |
| `cxc doctor` | Check dependencies and show the active configuration. |
| `cxc install-deps` | Show platform-specific dependency guidance. |
| `cxc backend list` | List discovered external backend plugins. |
| `cxc plugin install` | Install a `cxc-backend-<name>` plugin. |
| `cxc config` | Show the active configuration. |

## Validate and compile

Validate a scenario before compiling it:

```bash
cxc validate -i hello.cradle
cxc compile -i hello.cradle -o hello.yml
```

`cxc compile` writes intermediate YAML. It does not provision a testbed or run
scenario events.

To inspect the compiler stages as JSON, use:

```bash
cxc parse -i hello.cradle
cxc check -i hello.cradle
cxc dump-hir -i hello.cradle
cxc dump-ir -i hello.cradle
```

`cxc check --json` emits structured diagnostics. `dump-ir` is the backend input
for target-specific rendering.

## Render or deploy through a backend

Backends are external executables named `cxc-backend-<name>` and discovered on
`PATH`. Confirm discovery before selecting one:

```bash
cxc backend list
```

Render files without executing deployment stages:

```bash
cxc emit \
  -i hello.cradle \
  --target vagrant \
  -o ./output
```

Run the full workflow with a selected backend:

```bash
cxc deploy \
  -i hello.cradle \
  --backend vagrant \
  --stage all
```

The `--stage` option can select an individual deployment stage such as
`boot`, `provision` or `events`. `cxc deploy` may provision and execute events;
`cxc emit` only generates files. Backend-specific options can be repeated as
`--backend-arg key=value`.

Destroy a deployment with:

```bash
cxc destroy --deploy-dir ./output/HelloWorld
```

The selected backend owns the target-specific behavior and dependencies.

## Import and extract

Convert a static Vagrant/Ansible deployment into validated CRADLE source:

```bash
cxc import \
  --from /path/to/deployment \
  --name ImportedLab \
  --output scenarios/ImportedLab.cradle
```

The importer is conservative: dynamic Ruby, Ansible includes, roles and
arbitrary module behavior cannot be reconstructed automatically.

Extract forensic data from a deployment:

```bash
cxc extract \
  --scenario HelloWorld \
  --deploy-dir ./output/HelloWorld
```

Extraction is separate from compilation, rendering and deployment.

## Dependencies and configuration

Check the tools required by discovered backends and inspect the active
configuration:

```bash
cxc doctor
cxc install-deps
cxc config
```

The v0.16.0 configuration includes forensic and dataset directories, artifact
locations, deployment defaults, hardware defaults and per-backend options.
Pass a configuration file globally:

```bash
cxc --config ./config.toml doctor
```

## Artifacts and completions

Generate one artifact or a complete artifact project:

```bash
cxc generate-artifacts -i artifact.yml -o ./build
cxc generate-artifacts -i index.yaml -o ./build --project
```

Generate shell completion scripts with:

```bash
cxc completions bash
```

For command-specific options, use the help output supplied by the same
CradleXC build:

```bash
cxc <command> --help
```
