# Contribute a Cyber Range

Contribute scenarios to [cradle-lang/scenario-lib](https://github.com/cradle-lang/scenario-lib.git).
Keep the CRADLE specification, configuration modules, heuristics, scripts and
artifacts together in that repository. Validated contributions reach the
[Cyber Range Collection](/collection/) through a separate website review PR.

This guide follows scenario-lib's LLM-assisted article workflow. The LLM writes
an `index.md` draft from your existing scenario files; it does not generate or
validate a working CRADLE specification. You can also write the article manually
using the command in [Import without an LLM](#import-without-an-llm).
See the [scenario-lib README](https://github.com/cradle-lang/scenario-lib#readme)
for the full repository reference.

## 1. Prepare your checkout

Install Git, **Node.js 22 or newer**, and npm. Fork
[scenario-lib](https://github.com/cradle-lang/scenario-lib.git) if you do not have
write access. Replace `YOUR-GITHUB-USERNAME` with your account; contributors
with write access can clone upstream instead:

```bash
git clone https://github.com/YOUR-GITHUB-USERNAME/scenario-lib.git
cd scenario-lib
git switch -c add-my-range
npm ci
```

For an existing checkout, start from an up-to-date `main` and create a contribution
branch. Run the remaining commands from the **scenario-lib repository root**.
Scenario folders belong in `scenarios/`; `library/scenarios/` is the website's
import destination.

## 2. Configure the LLM connection

Create `.env` beside `package.json` by copying `.env.example` if `.env` does not
already exist. In Bash or Zsh:

```bash
if [ ! -f .env ]; then
  cp .env.example .env
fi
```

Edit `.env` with your server's API base URL, model and key. For example:

```dotenv
SERVER="https://soclaas-api.comp.nus.edu.sg/v1"
REMOTE_LLM_MODEL="qwen3.6:35b"
REMOTE_LLM_API_KEY="your-key-here"
```

Use a model available on your server. The endpoint must support OpenAI-compatible
Chat Completions. Include `/v1` in `SERVER` when your server requires it. If
`REMOTE_LLM_MODEL` is omitted, the generator selects the first model returned by
`GET /models`. The key may be empty only when the server allows unauthenticated
access. Shell environment variables take precedence over `.env`.

The generator sends selected scenario text to this server. Keep credentials out
of the scenario files and never commit `.env`; it is ignored by Git. Image and
binary contents are not sent, and hidden files and TOML files are excluded.
The default input limit is 100000 characters, configurable with
`LLM_MAX_INPUT_CHARS`; review the command's omitted/truncated-file report.

## 3. Import a scenario and generate its article

Prepare a source folder such as `~/Downloads/MyRange` containing a complete
specification and its supporting files. Then import it under a new folder ID:

```bash
npm run library:new -- scenario my-range --from "$HOME/Downloads/MyRange" --generate-index
```

This creates `scenarios/my-range/`, copies selected source files and generates
`index.md` with **`draft: true`**. IDs use lowercase letters, digits and hyphens.
Existing scenario folders are never overwritten; choose another ID or edit the
existing folder directly. The original source folder is unchanged.

The source must contain `scenario.cradle` or exactly one top-level `.cradle` file.
A uniquely named specification such as `MyRange.cradle` is copied as
`scenario.cradle`. If several specifications exist, name the main one
`scenario.cradle` before importing and review links to any renamed file.

The importer copies top-level specifications, README/article files, images and
supported scripts. It also copies these folders recursively:

- `config/`, `configs/`, `configuration/`, `configurations/`.
- `heuristic/`, `heuristics/`, `artifact/`, `artifacts/`.
- `script/`, `scripts/`, `img/`, `imgs/`, `image/`, `images/`.

TOML files, `.git`, `node_modules` and `__pycache__` are skipped. Other top-level
files and folders, such as `objects/`, must be added manually when needed.
Selected symbolic links are rejected. Check that every runtime dependency is
included or documented.

An authored `index.md` or `index.mdx` in the source is preserved during import.
To generate or replace the article for an existing scenario, use:

```bash
npm run library:describe -- my-range --force
```

`--force` permits replacement of an existing article. Without it, the command
preserves an existing article and reports an error. Failed generation keeps the
copied source files and current article intact. Invalid formatting or local
links receive one correction attempt before generation fails.

### Import without an LLM

Omit `--generate-index` to import the same source and create a draft article
from the template, or preserve an existing article:

```bash
npm run library:new -- scenario my-range --from "$HOME/Downloads/MyRange"
```

This command needs no `.env`, API key or LLM server. Write
`scenarios/my-range/index.md` yourself, then continue with the review and
validation steps below. Run only one of the import alternatives for a given ID.

To start from an empty template instead of importing a folder:

```bash
npm run library:new -- scenario my-range
```

Replace the comment-only `scenario.cradle` stub with a complete specification
and add supporting files before validation or article generation.

## 4. Review the draft

Review `scenarios/my-range/index.md` against the specification and supporting
files. LLM generation does not run compiler, deployment or runtime tests. Correct
unsupported claims and distinguish intended behavior from recorded test results.
Complete the purpose, topology, exercise sequence, setup, expected results,
dependencies, validation evidence, attribution and licensing sections.

Published articles require these front matter fields:

```yaml
---
title: My Range
description: Describe what this scenario demonstrates.
source: Original author or organization
category: ICS
tags: [Example, Training]
requirements: Document the backend, images, configs and artifact dependencies.
draft: true
---
```

`tags` must be a non-empty list. Do not add `id` or `slug`; the folder supplies
the scenario ID. Keep exactly one article and use **`index.md` for website
export**; convert an `index.mdx` article before exporting.

Retain the specification download and link supporting files relative to the
scenario folder:

```markdown
[Download the specification](./scenario.cradle)
[Setup script](./scripts/setup.sh)
![Topology](./images/topology.png)
```

Use only files you can redistribute and record their authorship and license.
Keep `draft: true` until the entry is ready, then set `draft: false` for website
publication. Drafts still undergo catalogue, compiler and dependency checks.

### Artwork and supporting files on the website

The optional `artwork` field selects `auto`, `network`, `enterprise` or
`monitoring`. `auto` uses light blue artwork for one network and dark blue
artwork for multiple networks.

A source scenario can use a local PNG, JPEG, WebP or GIF `thumbnail` with
`thumbnailAlt`. However, the website handoff exports only `index.md` and
`scenario.cradle`: it omits custom thumbnails, converts image embeds to source
image links and rewrites supporting-file links to the source commit. The synced
website entry uses built-in artwork. Keep supporting assets in scenario-lib so
readers can retrieve them from those links.

## 5. Check the contribution

After reviewing the article and editing metadata, update the tracked catalogue
and run the local checks:

```bash
npm run catalog:update
npm run check
npm run library:catalog
```

`npm run check` checks articles, the root catalogue and script tests. It does not
run CXC or a simulation. `library:catalog` generates the published-article
catalogue in ignored `dist/catalog.json`; commit the root `catalog.json` instead.

For compiler and configuration/heuristic dependency checks, install
[CradleXC](/docs/getting-started/install-cradlexc), ensure `cxc` is on your PATH,
and clone the shared library if you do not already have a checkout:

```bash
git clone https://github.com/cradle-lang/cradle-lib.git .reference-cradle-lib
npm run library:validate -- --library .reference-cradle-lib --scenario my-range
```

Skip the clone when that folder exists. Validation checks the specification and
resolves configuration and heuristic modules from the scenario and cradle-lib.
Reports are written to `scenario-output/validation.json` and
`scenario-output/validation.md`. The command fails if CXC is unavailable; if you
cannot run it locally, state that in the PR and inspect the mandatory GitHub
validation results.

These checks do not provision machines, verify runtime images, execute scripts
or run exercise events. Document any separate runtime tests and the compiler,
backend and testbed versions used.

## 6. Submit and publish

Commit the complete scenario folder and updated root catalogue. Review the
staged files before committing:

```bash
git add scenarios/my-range/ catalog.json
git diff --cached
git status --short
git commit -m "Add my-range scenario"
git push -u origin add-my-range
```

Open a PR into **`cradle-lang/scenario-lib`'s `main`**. List the checks actually
run and any compiler or runtime checks not run. Resolve failing CI before merge.
Keep `.env`, generated reports, `node_modules` and export bundles out of the
commit.

With the repository's website integration configured, publication proceeds as
follows:

1. Maintainers merge the scenario PR into scenario-lib's `main`.
2. **Validate scenarios** checks all scenarios, including drafts, with CXC and
   dependency validation.
3. After successful validation of the latest `main`, the notification workflow
   sends the validated revision and run ID to the website.
4. The website verifies the snapshot, builds it and opens or updates a review PR.
5. Maintainers review and merge the website PR. Its Pages workflow publishes
   entries with `draft: false`.

A scenario merge alone does not publish the website. After the website deployment
succeeds, verify the entry at
`https://cradle-lang.org/collection/?scenario=my-range` and its article at
`https://cradle-lang.org/library/scenarios/my-range`. Check the specification
download and supporting-file links. See the
[website handoff documentation](https://github.com/cradle-lang/scenario-lib#website-handoff-after-merging-to-main)
for integration setup and retry instructions.
